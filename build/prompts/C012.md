## Scope
Every DTO and enum the four apps share, generated against backend/contracts/. This is the single
definition of the wire shapes. ADD: [AL-09, AL-47, AL-48, D-10].

**Fences — do not cross these:**
- Enums are exhaustive and match the DB CHECK domains exactly — no client-invented values.
- Money is a value type over integer minor units. A raw Double for money is a bug.

## Deliverables
- shared/kmp/src/commonMain/kotlin/data/models — kotlinx.serialization DTOs for every D3 request/response
- canonical enums — VehicleType (AL-09), ServiceMode, RideState, PaymentState (incl. QrClaimedByPassenger/DriverConfirmedQR), Role, FleetRole, PackageSize, DocumentKind, CallType (free_voip|direct_dial), Language (si|ta|en)
- Money (minor units, LKR), GeoPoint, ProblemDetails, Page<T> cursor envelope
- PositionSample — canonical position event schema (ADD Appendix A)
- round-trip serialization tests against contract examples

## Definition of Done
- every DTO round-trips through kotlinx.serialization against the example payloads in backend/contracts/
- RideState and PaymentState enumerate exactly the values in the DB CHECK constraints
- no user-facing string literals are embedded in models (trilingual resources live in the apps)
