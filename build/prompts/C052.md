## Scope
SOS for both passengers and drivers, scoped trip-share tokens, vehicle reports and driver blocks.
ADD: [D-33, D-34, P-09, P-12, AL-13, AL-44].

**Fences — do not cross these:**
- SOS is a p99 <= 5 s SLO from button tap to SMS dispatched. Design for it, then prove it.
- Share tokens are trip-scoped, TTL-bounded (trip end + 1 h), revocable and rate-limited (60 req/min). No historical replay (D-34).
- Token access is metered; a dead token returns zero ride data.

## Deliverables
- POST /v1/sos (passenger or driver) -> parallel primary + secondary SMS + admin live-feed channel + safety.sos_events; GET history
- safety.trip_share_tokens issue/revoke with scopes package_recipient | proxy_rider | pickup_confirm and access metering (AL-44)
- POST /v1/reports/vehicle feeding reputation-svc; 3 confirmed reports -> auto-delist
- POST/DELETE /v1/drivers/{driverId}/block consulted by dispatch-svc and fanout-svc
- safety.location_request_audit persistence (P-12) and the admin report queue

## Definition of Done
- SOS reaches both SMS gateways in parallel and records per-gateway status
- the driver SOS path uses the driver's emergency contact from iam (AL-13)
- an expired or revoked token returns 410 with no ride data in the body
- a blocked driver is never offered that passenger's ride
