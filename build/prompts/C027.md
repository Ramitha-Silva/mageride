## Scope
The identity data plane: profiles, the nine-role deny-by-default RBAC, preferences, saved
addresses, emergency contacts, and the eager-fetch login payload.
ADD: [AL-06, AL-13, AL-14, AL-26, AL-27, P-03, E-06].

**Fences — do not cross these:**
- Deny-by-default. A privileged endpoint with no explicit permission entry must 403, not fall through.
- Language is set in onboarding and Settings only — never on Edit-profile (AL-26).
- PDPA fulfilment lives in admin-bff (C065); iam only records the request.

## Deliverables
- GET/PUT /v1/users/me, driver + passenger profile surfaces, notification preferences
- iam.roles / user_roles / fleet_members + policy evaluation matching URD §2.3 exactly
- iam.user_prefs (language si/ta/en, default_payment cash|lankaqr|onepay), operating_city_code (AL-27)
- iam.saved_addresses — Home/Work + label + line1/2/3 + geo (AL-26, US-22.2)
- iam.emergency_contacts for driver SOS fan-out (AL-13)
- GET /v1/users/lookup-by-phone -> {registered:bool} for proxy booking, phone hashed at rest (P-03)
- eager-fetch login payload — profile + saved addresses + payment metadata + active trip + config (AL-14)
- DELETE /v1/users/me -> pdpa.requests row

## Definition of Done
- the RBAC matrix test covers every (role, privileged endpoint) pair in URD §2.3 with an explicit allow/deny
- a user holding two roles gets the union of permissions
- an unregistered phone lookup returns registered:false and stores only a hash
- the login payload matches the AL-14 eager-fetch shape in one round trip
