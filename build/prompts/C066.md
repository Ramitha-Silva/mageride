## Scope
The stateless, no-login BFF serving the six SCR-WT web-subview pages. The share token IS the
credential. ADD: [AL-44, AL-45, AL-48, D-33, D-34, P-02, P-09, P-10, P-14].

**Fences — do not cross these:**
- No Bearer auth and no session. Responses are shaped strictly by token scope — a recipient never sees the sender's number, a proxy rider never sees the booker's payment instruments.
- `POST /public/track/{token}/call` is REMOVED (AL-48). The snapshot carries `driver.phone` for a plain tel: link instead.
- A dead, expired or unknown token returns zero ride data. Rate-limit per token AND per IP.

## Deliverables
- GET /public/track/{token} — scope-shaped snapshot for package_recipient | proxy_rider | pickup_confirm
- GET /public/track/{token}/live — SSE stream over the same ride/geocell channels with a ?since cursor long-poll fallback
- POST /public/track/{token}/pickup/confirm | /decline — feeds the same rides.location_requests state machine; decline stores no coordinates (AL-45)
- POST /public/track/{token}/sos — dual-gateway SMS to the booker + admin live feed, safety.sos_events(source='web')
- GET /public/track/{token}/receipt — terminal states with outcome otp_verified | photo_proof | cod_collected | disputed
- per-token + per-IP Redis token buckets, access metering (last_access_at, access_count), uniform 404/410/429 errors

## Definition of Done
- each scope returns exactly the documented field set and nothing more
- an expired token returns 410 with no ride data in the body
- a web pickup-confirm resolves the same location request an in-app confirm would
- the SSE stream survives a reconnect and resumes from the cursor
- no endpoint leases a DID or returns a masked number
