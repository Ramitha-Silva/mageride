## Scope
The Driver Android application shell that all eight screen groups plug into: module setup, theme,
trilingual resources, navigation, map, and the native background services that KMP cannot own.
ADD: [R-07, R-17, AL-12, AL-31, AL-43, D-30].

**Fences — do not cross these:**
- No screen implementations here — this is the host. Screens belong to C068-C075.
- The dashboard has NO top-left hamburger; navigation is the bottom-nav Menu tab (AL-31).
- Background GPS + MQTT stay native (ForegroundService); KMP supplies config and cadence only.

## Screens (baseline = wireframes)

## Deliverables
- apps/driver-android module — Koin DI, MageRideTheme from the D2 §0.2 tokens (M3 colorScheme, Outfit + Inter type scale, spacing/radius/elevation)
- trilingual resources — values/, values-si/, values-ta/ with zero hardcoded user-facing strings
- NavHost + Scaffold + bottom navigation (Menu tab entry point), deep-link handling for FCM payloads
- MapLibre GL Native setup over PMTiles (light/dark styles, SymbolLayer markers by vehicle token, cluster, heading arrow, accuracy + 100 m geofence circles)
- ForegroundService — FusedLocationProviderClient + HiveMQ MQTT publish, adaptive cadence from KMP, gps_buffer replay on reconnect (R-17)
- Play Integrity attestation provider + Android Keystore device binding wired into the KMP expect/actual
- FCM high-priority receiver, offline banner host, app-update gate host

## Definition of Done
- the app builds, launches and renders the themed shell with the bottom-nav Menu tab and no hamburger
- every string comes from a resource file and all three locales resolve
- the foreground service survives Doze and keeps publishing at the phase-appropriate cadence
- a buffered GPS backlog replays on veh/{vehicleId}/pos/replay with monotonic seq after reconnect
- Play Integrity tokens reach the X-Attestation header on sensitive calls
