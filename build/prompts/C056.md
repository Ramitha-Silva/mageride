## Scope
GTFS-backed public-transport routing for Mode A discovery, plus the Google-Maps paste-link
resolver. ADD: [AL-17, AL-18, AL-20, AL-55].

**Fences — do not cross these:**
- No Google APIs. Short maps.app.goo.gl links are resolved by following the redirect and parsing coordinates.
- Destination input is a geo-location; this service never accepts a typed route number as a destination (AL-17).
- SCR-PA-009's no-coverage degradation is a safety net for genuine feed gaps, not the expected launch state (AL-55).

## Deliverables
- GET /v1/transit/options?from&to — ALL direct routes (route_id, short_name, headsign, shape) + transit (>=1 transfer) options, each tagged Direct/Transit + PUBLIC
- GET /v1/transit/routes/{routeId} — detail, shape polyline, nearest halts
- GET /v1/geo/parse-maps-link — resolve a Google Maps URL (incl. short links) to {lat,lng} (AL-20)
- in-memory route/stop caches reloaded on the transit_feed_activated NOTIFY (<= 60 s)
- degradation response when no active feed exists (live buses + private tiers shown, route matching hidden)

## Definition of Done
- a corridor with a known direct route returns it with the correct shape polyline
- all four Google Maps URL shapes (?q=, @lat,lng, /place/...@, short link) resolve or fail cleanly within 3 s
- activating a new feed version refreshes the cache within 60 s without a restart
- with no active feed the endpoint degrades rather than erroring
