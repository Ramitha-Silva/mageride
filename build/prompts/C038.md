## Scope
Production-grade MQTT -> Redpanda bridge: shared subscriptions for live and replay, partitioning
by vehicleId, offset management and replay throttling. ADD: [E-08, R-09, T-05, D-17].

**Fences — do not cross these:**
- Replay traffic uses its own consumer group at lower priority and a hard rate limit — it must never starve live samples (R-09).
- Partition key is vehicleId so per-vehicle ordering is guaranteed.

## Deliverables
- $share/posGroup/veh/+/pos/live and a parallel $share/posGroup/veh/+/pos/replay consumer group
- Redpanda producer keyed by vehicleId into telemetry.raw with per-partition offset commits
- replay throttle (20 samples/s/device, T-05) and broker-side 5 msg/s ceiling violation events into audit.events (D-17)
- graceful rebalance on replica loss with no duplicate ingest

## Definition of Done
- N replicas ingest each message exactly once (E-08) under a load test
- a replay flood is rate-limited without measurable added latency on live samples
- per-vehicle message order is preserved end to end
- a rate_violation event is emitted for a client publishing above 5 msg/s
