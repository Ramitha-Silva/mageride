## Scope
Vehicle lifecycle and sharing: CRUD, canonical types, the one-live-publisher rule, deactivation,
Mode B share grants and revocation, fleet-assigned vehicles, and OnePay merchant onboarding.
ADD: [AL-03, AL-09, AL-23, D-03, D-11, D-22, D-37, E-03].

**Fences — do not cross these:**
- Train (Mode A) registration is admin-only via admin-bff. The Driver App must expose no train path.
- Mode A/B vehicles and route permits belong to the Fleet Portal (C059), not the Driver App (AL-27).
- Document intake, OCR and the onboarding step machine are C029.

## Deliverables
- vehicle CRUD with the AL-09 vehicle_type CHECK, reg-no uniqueness in the active set (D-37), deactivate (US-2.16)
- GET /v1/vehicles/mine incl. temporarily-assigned fleet vehicles (US-13.9) as a separate group
- single active publisher selection + Redis lock:driver:{driverId} coordination (D-03)
- Mode B share grants + DELETE subscribers -> `share.revoked` outbox event (D-22)
- registry.driver_payouts OnePay merchant binding during approval (D-11)
- go-online eligibility projection consumed by dispatch (approved Mode C owned, or assigned/shared Mode A/B)

## Definition of Done
- only an APPROVED Mode C vehicle or an assigned/shared Mode A/B vehicle is go-live eligible (US-9.6)
- selecting a vehicle live releases the previous one atomically; two live vehicles per driver is impossible
- `share.revoked` is emitted through the outbox and carries the passenger id fanout needs
- no endpoint allows creating a train from a driver-role token
