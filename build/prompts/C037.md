## Scope
The two Mode C sub-kinds on top of the same aggregate: proxy booking (booker != rider) with the
location-request round trip, and package delivery with pickup/delivery OTPs, proof photos and
COD. ADD: [P-01..P-14, AL-21, AL-33, AL-45, AL-48].

**Fences — do not cross these:**
- Calls and notifications always reach the RIDER, never the booker (P-05).
- The counterparty's real phone number is exposed only post-accept, and never for rides cancelled before assignment (AL-48).
- Decline on a location request transmits NO coordinates (P-02).
- Still Mode C only — proxy and package ride on the ride-svc aggregate, never on trip-state-svc sessions (R-01).

## Deliverables
- proxy fields on request — isProxy, riderPhone, riderName, kind ∈ passenger|proxy|package; unregistered rider stored as a hash (P-03)
- POST /v1/location-requests + confirm/decline, 300 s TTL, booker WS group booker:{bookerId}:loc-req:{requestId} (P-02, P-13)
- package creation with two 4-digit HMAC-hashed OTPs, pickup/delivery verify endpoints, max 5 attempts -> 423 locked -> admin queue (P-07)
- proof-photo upload -> rides.proof_artifacts (P-10) and cod-collected -> CashOnDeliveryCollected (P-08)
- uncollected COD > 24 h timer -> Disputed (P-14); driver 3-sheet delivery events (AL-33)
- RiderNotRegistered path handing off to notification-svc for the pickup_confirm web token (AL-45)

## Definition of Done
- a proxy ride notifies both booker and rider on every state change, and the driver only ever sees the rider
- a declined location request stores the decision with no coordinates and falls back to the booker pin
- a sixth wrong pickup OTP returns 423 and raises an admin-queue item
- a package delivered by proof photo (recipient absent) reaches Completed with the artifact persisted
