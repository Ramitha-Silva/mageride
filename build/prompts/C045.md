## Scope
Server-side i18n and public reference data: notification templates, FAQ articles, broadcasts,
fare-tariff display strings and the admin-managed launch-city list.
ADD: [D-26, AL-27, AL-28].

**Fences — do not cross these:**
- Every user-facing string in every template exists in all three languages (si, ta, en) or the template is invalid.
- Only active operating cities are served publicly.

## Deliverables
- content.notification_templates / faq_articles / broadcasts with versioning + admin approval workflow
- GET /v1/content/templates/{key}?lang=, GET /v1/content/faq, admin broadcast publish
- GET /v1/config/cities — public, cacheable, from config.operating_cities (AL-27)
- driver + passenger onboarding carousel strings and illustrations (AL-28) served as content
- aggressive caching with an invalidation path on publish

## Definition of Done
- publishing a template missing a language is rejected with a clear error
- GET /v1/config/cities returns active rows only, ordered by sort_order, with name_si/ta/en
- a template change is visible to notification-svc within the documented cache TTL
