## Scope
All outbound push and SMS, including the latency-critical dispatch-offer path and the web-share
token minting for unregistered riders and recipients.
ADD: [E-01, D-27, D-33, P-02, P-09, P-12, AL-21, AL-44, AL-45].

**Fences — do not cross these:**
- Share tokens are minted server-side and SMSed. A token is never returned to a client (AL-44/AL-45).
- {'Per-booker location-request rate limits are hard limits': '5/hour, 30/day (P-12).'}
- No masked-number relay — the D-25 masked-SMS fallback was removed by AL-48.

## Deliverables
- FCM HTTP v1 batch + APNs HTTP/2 with exponential-backoff worker (D-27); high-priority offer push (FCM priority=high, APNs apns-priority:10 + content-available:1) and 3 s ack -> SMS fallback (E-01)
- SMS via Notify.lk primary + Dialog/Mobitel secondary in parallel for SOS (D-33)
- template rendering from content-svc in the user's language (si/ta/en) + per-type preferences (US-10.7)
- location-request data messages with Redis token-bucket limits and decline auditing (P-02, P-12)
- package recipient branch — registered -> FCM deep link to SCR-PA-021; unregistered -> SMS with a package_recipient share token (AL-21)
- pickup_confirm token minting (TTL 300 s, burned on use) for RiderNotRegistered (AL-45); proxy_rider token on driver accept
- low-balance, daily-fee, document-expiry, scheduled-ride, directional pre-expiry and broadcast notifications

## Definition of Done
- an offer push that is not acked within 3 s triggers the SMS fallback exactly once
- SOS SMS dispatch measures p99 <= 5 s in an integration test against both gateways (D-33)
- a 6th location request in an hour from the same booker is rejected
- every notification body is rendered in the recipient's language with no hardcoded strings
