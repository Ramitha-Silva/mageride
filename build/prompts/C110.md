## Scope
The GTFS Dataset Manager in the Configuration nav group: upload, validate, preview, activate,
history and rollback for the national transit feed.
ADD: [AL-54, AL-55, AL-56, D-35, US-28.1, US-28.2, US-28.3].

**Fences — do not cross these:**
- Admin and Super Admin only. Verification / Support / Finance / Auditor see no Transit-data nav entry.
- The feed is an EXTERNALLY PROVIDED file — this screen is the sole ingestion surface. Do not build an authoring UI (AL-56).
- A failed activation must leave the previously active feed live and say so.

## Deliverables
- upload dropzone (.zip only, <= 200 MB) with progress and sha256-duplicate inline error
- status stepper Uploaded -> Validating -> Validated / Failed with 2 s polling; failure shows the first 5 errors + Download error report (JSON/CSV)
- preview card — per-file counts, feed_info version, service date range, collapsible warnings, Activate with a confirm dialog naming the version being replaced
- activation spinner + success toast; version-history table with Active / Archived / Validated / Failed chips and Re-activate / View report / Download zip actions
- empty state for the pre-first-import day-0 case

## Definition of Done
- the screen matches its wireframe layout, controls, states and navigation for all seven documented states
- uploading a duplicate file shows the inline "already uploaded (version N)" error
- activating shows the confirm dialog with the outgoing version named, then the success toast
- re-activating an archived version performs a rollback with the same confirm flow
- a non-Admin role cannot reach the route
- every screen listed under `## Screens` is implemented to match the layout, controls,
  states and navigation shown in its wireframe — the wireframes are the team-approved
  baseline; any deviation requires a micro-change-set first. D2' still governs design
  tokens, styling rules and trilingual (Si/Ta/En) string resources.
