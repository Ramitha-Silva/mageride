## Scope
The verification workflow behind SCR-AP-003/003a/003b/003c: three queue feeds, per-field confirm,
the audited document viewer and fleet-org approval. ADD: [AL-29, AL-30, AL-39, AL-49, D-35].

**Fences — do not cross these:**
- The Verification Officer sees only PENDING items — auto-verified documents never enter the queue (AL-27).
- Approve unlocks only when every flagged field is confirmed.
- Document reads use short-lived signed object-storage URLs and emit a DOC_VIEW audit event (AL-39).

## Deliverables
- GET /admin/verification/queues/{driving_license,vehicle_registration,fleet_org} with search + status filter
- GET /admin/verification/{driverId|vehicleId|orgId} — flagged fields + attached documents (kind + signed thumb/full URL) + per-step breakdown
- PUT /admin/verification/{id}/fields/{key} confirm or edit-and-confirm; POST approve / reject with reason
- GET /admin/documents/{docId} — signed URL issue + DOC_VIEW audit
- fleet-org approval detail incl. payout-profile documents, setting payout_profiles.status (AL-49)

## Definition of Done
- approving with an unconfirmed flagged field is refused
- every document view produces exactly one DOC_VIEW audit row with the actor and doc id
- a rejected item returns to the driver with the reason and re-enters the queue on re-upload
- approving a fleet org's payout profile makes payTo available to subscription-svc
