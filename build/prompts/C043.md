## Scope
Hardware tracker ingest for the four protocol families, normalising binary frames into the
canonical PositionSample and publishing into EMQX as a server-side bridge user.
ADD: [T-01, T-03, T-04, T-05, T-11].

**Fences — do not cross these:**
- The canonical service name is `tcp-adapter`. D3 Part 1 also calls it `tracker-adapter-svc` — that is an alias only (D-DRIFT-2).
- MQTT-capable trackers bypass this service entirely and connect straight to EMQX.
- Ports 5023-5026 are TCP/UDP passthrough at HAProxy, never HTTP-routed.

## Deliverables
- adapter-gt06, adapter-jt808, adapter-h02, adapter-nmea-udp listeners on 5023-5026 (Kestrel raw TCP / SocketAsyncEventArgs / UDP)
- IMEI authentication against the provisioning Redis cache with sub-second revocation honouring (T-12)
- binary frame decoding -> PositionSample -> publish to veh/{vehicleId}/pos/live or /pos/replay
- downlink command frames from veh/{vehicleId}/cmd; LWT emulation publishing status=offline on socket half-close (T-04)
- sticky-by-IMEI-hash scaling notes + per-pod 10k socket budget

## Definition of Done
- a captured frame from each of the four protocol families decodes to the expected PositionSample in a golden test
- an unbound or revoked IMEI is refused at connect
- a half-closed socket publishes a retained status=offline within the configured window
- Mode C tracker GPS is accepted only while the driver is Online; Mode A is accepted regardless (T-11)
