## Scope
The Fleet Portal shell at `fleet.mageride.lk`: Next.js app, email/Google/Apple sign-in, org-scoped
navigation and the RLS-aware data layer. ADD: [AL-03, AL-52].

**Fences — do not cross these:**
- A fleet operates Mode A and/or Mode B only. Never surface a Mode C option (AL-03).
- Every read is org-scoped; a cross-org read must be impossible from the client and refused by the server.
- Owner / Manager / Viewer sub-roles gate the UI; Viewer sees no mutating control.

## Screens (baseline = wireframes)
- None. This component is the application shell for `specs/wireframes/web_fleet.html`;
  it owns no wireframe screen ID. Screens belong to the sibling screen-group components.

## Deliverables
- portals/fleet Next.js app consuming @mageride/tailwind-preset
- sign-in with Email+Password / Google / Apple, email verification, forgot-password/reset, identity link/unlink
- org-scoped nav with sub-role gating; pending-approval state blocking vehicle and assignment screens
- typed data layer to fleet-svc with problem+json rendering; i18n si/ta/en; responsive 375/768/1024, light + dark

## Definition of Done
- an unapproved org sees the pending-verification state and cannot reach vehicle or assignment screens
- a Viewer session renders no mutating control anywhere
- the shell renders correctly at all three breakpoints in both themes
- no runtime CSS-in-JS appears in the production bundle
