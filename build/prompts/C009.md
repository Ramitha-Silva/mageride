## Scope
Two dev compose files and the config they need: a SLIM stack (postgres + pgbouncer + redis +
redpanda + emqx + minio + migrate) that every later component uses for its verify command on the
shared VPS, and the FULL dev stack matching D7 §3. Plus env templates, HAProxy config, EMQX JWT
auth, and Redpanda topic bootstrap.

**Fences — do not cross these:**
- This is the DEV stack. The lightweight production replica deployment is C125 — do not deploy it here.
- Keep the replica stack DOWN while this runs; the box hosts both and ~17-20 GB will not fit alongside builds.
- Startup order is enforced by healthchecks; the `migrate` one-shot runs before app-services.

## Deliverables
- infra/docker-compose.dev.slim.yml — infra only, ~6 GB, for per-component verification
- infra/docker-compose.dev.yml — full set per D7 §3 (hot-path, app-services, fanout, tcp-adapter, haproxy)
- infra/env/.env.common.example + .env.app.example covering every variable in D7 §4
- infra/deploy/haproxy.cfg (443 / 8883 / 8084 / 5023-5026), emqx JWT + ACL config, redpanda topic bootstrap script
- infra/scripts/wait-healthy.sh, infra/scripts/dev-up.sh, infra/scripts/dev-down.sh

## Definition of Done
- both compose files pass `docker compose config`
- the slim stack reaches healthy for every container and the migrate job exits 0
- EMQX rejects a client whose JWT vehicleId claim does not match its publish topic
- Redpanda has telemetry.raw, telemetry.normalized, ride.events, dispatch.events, trip.events, audit.events after bootstrap
- env templates list every D7 §4 variable with a non-secret default or an explicit placeholder

## Verify
```
docker compose -f infra/docker-compose.dev.slim.yml config && docker compose -f infra/docker-compose.dev.slim.yml up -d && bash infra/scripts/wait-healthy.sh && docker compose -f infra/docker-compose.dev.slim.yml down
```
