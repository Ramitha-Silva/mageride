## Scope
Token lifecycle and device identity shared by all four apps. ADD: [D-29, D-30, E-02, AL-07,
AL-08].

**Fences — do not cross these:**
- Apps are Phone-OTP only. No Google/Apple/password paths in the mobile auth module (AL-07).
- The MQTT session JWT is a separate token with its own TTL — never reuse the 30-min API access token for MQTT (E-02).

## Deliverables
- shared/kmp/src/commonMain/kotlin/domain/auth — OTP request/verify flow, session state machine, logout, single-active-device-per-app handling (AL-08)
- access-token (30 min RS256) + opaque rotating refresh handling with single-use semantics
- MQTT session-JWT acquisition and renewal, TTL = max(active-ride + 2 h, 4 h), bound to (vehicleId, deviceId, rideId?) (E-02)
- expect/actual SecureStore — Android Keystore / iOS Keychain + Secure Enclave
- expect/actual AttestationProvider — Play Integrity / App Attest token supply for the X-Attestation header

## Definition of Done
- a 401 triggers exactly one refresh attempt and replays the original request once
- a revoked-session response clears local state and routes the app to login
- the MQTT token is renewed before expiry while a ride is active, independent of API-token failures
- secrets are never written to plain settings storage in either expect/actual implementation
