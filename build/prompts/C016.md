## Scope
Money-side domain logic shared by both apps: fare display, payment state, daily fee, wallet,
vouchers, credit transfer, and Mode B subscription billing. ADD: [D-10, D-13, E-10, P-04, P-08,
R-05, R-19, AL-01, AL-15, AL-19, AL-22, AL-24, AL-47].

**Fences — do not cross these:**
- Mode C tiers show PRICE ONLY before a driver is matched — no ETA, no distance (AL-19).
- Driver-to-driver credit transfer moves the EXACT value. Any commission on transfer is a bug (AL-01).
- The client never computes the authoritative fare; it renders the server's estimate and final.

## Deliverables
- shared/kmp/src/commonMain/kotlin/domain/fare — tariff model (1st km + per km + peak/night), estimate rendering, rounding rules (D5 §1.3)
- payment state machine projection incl. driver-QR attestation (QrClaimedByPassenger -> DriverConfirmedQR) and the >5 min unconfirmed nudge (AL-47)
- daily-fee model — 7 tiers, first-trip-free, Asia/Colombo fee_date, low-balance threshold (D-13, US-9.9)
- wallet domain — balance, top-up methods (OnePay card/wallet, LankaQR deep link; NO bank transfer), voucher purchase discount tiers, credit transfer request/approve/send
- Mode B subscription billing cycle (1st-of-month vs join-anniversary), per-subscriber fare, payment methods (AL-24)

## Definition of Done
- fare rounding matches D5 §1.3 exactly for a table of spec-derived cases
- a credit transfer of X debits X and credits X in the projected ledger with zero fee
- the daily-fee model treats the first trip of an Asia/Colombo day as free and charges before the second
- no bank-transfer top-up path exists anywhere in the module (AL-05)
