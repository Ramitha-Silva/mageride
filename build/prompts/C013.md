## Scope
The Ktor HTTP layer: one typed client interface per backend service, plus the cross-cutting
conventions every call obeys. ADD: [R-14, R-18, D-30, D-31].

**Fences — do not cross these:**
- The client never invents endpoints. If a call is missing from backend/contracts/, that is a spec gap to report, not a place to improvise.
- Do not put domain rules here — C015/C016 own them.

## Deliverables
- shared/kmp/src/commonMain/kotlin/data/api — typed clients for iam, registry, ride, dispatch, fare, subscription, wallet, query, transit, safety, support, content, voip, notification
- Ktor HttpClient config — JSON, timeouts, logging, exponential backoff + circuit breaker per D6 §8.3
- request pipeline — Bearer + refresh-on-401, Idempotency-Key (ULID) on every POST, X-App-Version / X-Platform / X-Attestation
- RFC 7807 -> typed MageRideError mapping keyed on the stable kebab code; 426 surfaces as an UpgradeRequired signal
- cursor pagination helper and repository interfaces consumed by the app layer

## Definition of Done
- every contract file has a matching typed client covering all its operations
- a 409 offer-already-accepted and a 410 offer-expired map to distinct typed errors
- retrying a POST reuses the original Idempotency-Key rather than minting a new one
- MockEngine tests cover auth refresh, 426 upgrade, and rate-limited 429 backoff
