## Scope
The Admin Portal application shell at `admin.mageride.lk`: Next.js app, session handling,
role-scoped navigation, the data layer to admin-bff and the shared page chrome.
ADD: [AL-02, AL-06, AL-37, AL-52, D-35].

**Fences — do not cross these:**
- No driver-facing or passenger-facing pages. Drivers never log in here.
- Role-scoped menus are deny-by-default — a role with no permission sees no nav entry AND gets no route.
- No MFA step anywhere in sign-in (AL-37).

## Screens (baseline = wireframes)
- None. This component is the application shell for `specs/wireframes/web_admin.html`;
  it owns no wireframe screen ID. Screens belong to the sibling screen-group components.

## Deliverables
- portals/admin Next.js app (TypeScript, App Router) consuming @mageride/tailwind-preset
- session handling for password / Google sign-in against iam-svc; failed-attempt lockout surfaced
- role-scoped nav with the Verification, Directory (Passengers/Drivers/Vehicles), Finance, Configuration (incl. Transit data) and Audit groups
- typed data layer to admin-bff with problem+json error rendering and audit-aware mutation helpers
- i18n si/ta/en, responsive layout at 375 / 768 / 1024, light + dark

## Definition of Done
- a Support/CSR session sees only the nav entries URD §2.3 permits, and direct-URL access to a forbidden route 403s
- sign-in completes with no second factor
- the shell renders correctly at all three breakpoints in both themes
- no runtime CSS-in-JS appears in the production bundle
