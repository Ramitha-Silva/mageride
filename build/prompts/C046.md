## Scope
The driver wallet on a balanced double-entry ledger: in-app top-ups, bulk credit vouchers, and
driver-to-driver credit transfers. ADD: [D-09, D-12, AL-01, AL-05, AL-15, AL-34].

**Fences — do not cross these:**
- Bank-transfer top-up is REMOVED (AL-05). Do not build a receipt flow or a manual reconciliation queue for it.
- "Reseller" is not a role, account or capability (AL-01). One wallet per driver; transfers move the EXACT value with no commission.
- Credit requests are Driver-ID only — the QR-scan path was removed (AL-34).

## Deliverables
- GET /v1/wallet/{userId} + /transactions; balanced double-entry postings (billing.accounts / journal_entries / journal_postings)
- POST /v1/wallet/topup/card | /onepay | /lankaqr (deep link to bank app, QR fallback — AL-15) + OnePay webhook and LankaQR confirm
- POST /v1/wallet/voucher/purchase — per-denomination discount from billing.voucher_discount_tiers applied only at purchase, credited to the buyer's own wallet
- POST /v1/wallet/credit-transfer/initiate + request/approve/reject flow by Driver ID; GET /v1/wallet/{driverId}/transfers
- wallet.debited / wallet.credited outbox events invalidating the dispatch balance cache (D-08)
- low-balance detection feeding notification-svc (US-9.9)

## Definition of Done
- every ledger entry balances to zero; the DB trigger rejects anything else
- a Rs 1,000 voucher at a 10 % tier debits Rs 900 and credits Rs 1,000 exactly once, idempotent on the gateway reference
- a credit transfer of X debits the sender X and credits the recipient X — no fee row is ever written
- a replayed OnePay webhook (same provider_transaction_id) credits the wallet only once
- no bank-transfer endpoint or table is referenced anywhere
