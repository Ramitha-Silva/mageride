## Scope
Complete the authentication half of iam-svc: real SMS OTP, the full token model, per-surface
sign-in, device binding, and the decoupled MQTT session JWT.
ADD: [D-29, D-30, D-32, E-02, AL-07, AL-08, AL-37].

**Fences — do not cross these:**
- Apps (Passenger + Driver) are Phone-OTP only — no Google on apps. Admin Portal = password or Google, NO MFA (AL-37). Fleet Portal = email+password / Google / Apple.
- D3 §0 and D7 §4.2 still carry pre-AL-37 MFA wording; AL-37 wins. Do not implement a TOTP step.
- Profile, RBAC and saved addresses are C027.

## Deliverables
- Notify.lk OTP sender + Redis token-bucket rate limiting (60 s resend, 5/h) with secondary-gateway fallback
- JWKS key rotation, RS256 signing, opaque refresh rotation with single-use + reuse detection
- per-surface sign-in — phone OTP (apps), password/Google (admin), email+password/Google/Apple (fleet)
- device binding + iam.devices, single-active-device per app revocation (AL-08)
- POST /v1/auth/mqtt-token — TTL = max(active-ride + 2 h, 4 h) bound to (vehicleId, deviceId, rideId?) (E-02)
- failed-attempt lockout + optional IP allow-list for internal roles (AL-37 compensating controls)

## Definition of Done
- all sign-in surfaces issue the same unified account token with the correct claim set
- refresh-token reuse is detected and revokes the session family
- the MQTT token survives an API-token refresh failure for the life of an active ride
- no MFA/TOTP code path or iam.user_mfa usage exists anywhere
