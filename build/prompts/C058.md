## Scope
Fleet organisation identity: org CRUD behind a Verification-Officer approval gate, org-scoped
sub-roles with row-level security, and the bank & payout profile that Mode B money depends on.
ADD: [AL-03, AL-49, AL-51].

**Fences — do not cross these:**
- A fleet operates Mode A (free) and/or Mode B only. Mode C is never a fleet option (AL-03).
- An org cannot onboard vehicles or assign drivers until a Verification Officer approves it.
- Every read is row-level-security scoped to the caller's org. A cross-org read is a security bug.

## Deliverables
- POST/GET /v1/fleets with PENDING -> APPROVED/REJECTED gate feeding the admin fleet-org queue
- org-scoped Owner/Manager/Viewer sub-roles provisioned by the Fleet Owner (iam.fleet_members)
- GET/PUT /v1/fleets/{id}/payout-profile + POST payout-profile/documents (bank_statement | passbook_first_page | lankaqr_code)
- versioned registry.fleet_payout_profiles with exactly one verified row per org; any edit re-enters pending_verification
- classification gate — PUT vehicles/{vid}/classification {paid} returns 409 payout-profile-not-verified until Verified (AL-49)
- RLS policies + a fleet-scoped read path into telemetry and rides

## Definition of Done
- an unapproved org receives 403 on every vehicle and assignment endpoint
- a Viewer cannot mutate anything; a Manager cannot change the payout profile
- editing a verified payout profile re-enters pending while Paid subscriptions keep collecting against the last verified snapshot
- a cross-org read attempt is refused by RLS, not by application filtering alone
