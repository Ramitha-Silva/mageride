## Scope
Directional Travel (Destination Filter) as an extra candidate predicate on the Wave-2 dispatcher.
ADD: [DT-01..DT-08].

**Fences — do not cross these:**
- The predicate runs AFTER all hard gates and can only REMOVE candidates — never add ineligible ones or relax a bound (DT-05).
- Manual turn-off still consumes a daily use (DT-03).
- A directional driver being the only nearby candidate must not block the ride — it proceeds exactly as today (DT-06).
- Directional Travel is Mode C dispatch only. It never touches trip-state-svc Mode A/B sessions (R-01).

## Deliverables
- POST/GET/DELETE /v1/standby/directional with usesRemaining + timeRemaining (DT-01, DT-08)
- Redis driver:directional:{driverId} hash + PEXPIRE and the per-day INCR counter (Asia/Colombo)
- the DT-02 predicate — bearing alignment <= theta_max, pickup detour <= detour_max, drop-off progress > progress_min — with metrics persisted into candidate_scores.breakdown.directional
- Quartz durable expiry (dispatch.timers kind='directional_expiry') + clear on manual off / offline / LWT, emitting directional.cleared (DT-04)
- PUT /v1/admin/dispatch/directional-config for theta_max, detour_max, progress_min, max_uses_per_day, max_duration, clear_on_first_trip
- 10-minute pre-expiry reminder hand-off to notification-svc

## Definition of Done
- a ride heading away from the driver's destination is filtered out and the decision is auditable from candidate_scores
- the third activation in one Asia/Colombo day returns 409 with the daily-use limit reason
- going offline clears the active filter and emits directional.cleared
- no reputation or acceptance-rate penalty is applied when no directional hires arrive (US-6A.23)
