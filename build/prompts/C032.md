## Scope
Promote the skeleton ride aggregate to the full specification: the complete state machine, the
server-owned cancellation and no-show matrix, durable timers, grace windows, idempotency and the
transactional outbox. ADD: [R-01..R-05, R-13..R-20, E-09, D-05, AL-16].

**Fences — do not cross these:**
- ride-svc is the SOLE authoritative writer of the ride aggregate. dispatch-svc offers; it does not write ride state.
- Mode A/B never appears here (R-01).
- No direct HTTP to other services for state changes — outbox only.

## Deliverables
- full state machine incl. CancelledByRiderBeforeAccept/AfterAccept, CancelledByDriver, ExpiredNoDriver, NoShowRider, NoShowDriver
- cancellation + no-show matrix per §11.12 with reason codes and the Rs 50 penalty event (D-05)
- rides.timers + Quartz.NET clustered scheduler — offer_expiry, arrival_grace, no_show, payment_pending, offline_grace (R-04)
- per-state grace windows on EMQX LWT offline (60 s after accept, 120 s after arrive, 5 min in progress, 10 min at payment) (R-15, R-16)
- rides.transitions immutable audit + command_log replay + outbox with LISTEN/NOTIFY
- internal mTLS routes — system-cancel, payment-settled, saga-state
- stuck-state metrics feeding the R-20 SLOs

## Definition of Done
- every cell of the D5 §7 cancellation matrix is covered by a test asserting the resulting state and money effect
- three consecutive post-acceptance rider cancellations disable booking; a completed ride resets the counter (AL-16)
- a Redis flush does not lose an offer expiry — the Quartz backstop still fires (R-04)
- driver earning is never posted before the payment reaches a terminal state (R-05)
