## Scope
Mode C fare computation and driver earnings: tariffs, peak/night windows, the upfront estimate,
GPS-distance correction, the final fare and the earnings ledger.
ADD: [E-04, E-10, R-05, AL-19, D-05].

**Fences — do not cross these:**
- Mode C tiers expose PRICE ONLY before a driver is matched — no ETA, no distance (AL-19).
- Mode B has no per-trip fare. Mode A has no fare at all.
- Driver earning posts only once the payment reaches a terminal state (R-05).

## Deliverables
- fares.tariffs + fares.peak_windows model with admin configuration through admin-bff
- GET /v1/fare/estimate returning a signed fareEstimateToken consumed by POST /rides/request
- POST /v1/fare/calculate — Kalman filter + accuracy-weighted resample before distance summation (E-04)
- fares.driver_earnings aggregation per driver per day; tip capture credited to the wallet (E-10)
- cross-trip Rs 50 cancellation settlement applied idempotently on the next completed trip (D-05)

## Definition of Done
- the fare formula reproduces every worked example in D5 §1.1 to the minor unit
- rounding follows D5 §1.3 exactly and money never touches a floating-point type
- raw-GPS distance inflation is measurably reduced by the filter on a replayed noisy track
- an estimate token cannot be reused for a different pickup/dropoff pair
